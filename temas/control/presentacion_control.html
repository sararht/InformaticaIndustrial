Contexto y fundamentos del control

El control de procesos por computador

Definición

Un proceso o sistema es un conjunto de elementos físicos que cumplen una función común.

  • Entradas: acciones que se pueden modificar para afectar al sistema.
  • Salidas: magnitudes físicas que se desean controlar.
  • Referencia: valor deseado para la salida.
ProcesoEquipo físico
→
SalidaTemperatura, velocidad, posición...
ControlPrograma
→
EntradaActuador / energía

Variables que intervienen

Conceptos clave

  • Referencia o consigna: valor deseado.
  • Error: diferencia entre referencia y salida.
  • Acción de control: decisión aplicada al sistema.

Idea central

El programa lee la salida, calcula el error y modifica la entrada con la intención de hacer que el error tienda a cero.

e(k) = r(k) - y(k)

Ejemplos clásicos de sistemas

Sistema térmico

Calefacción de un fluido o entorno; la temperatura es la variable de salida.

Sistema mecánico

Motor y guía lineal; velocidad o desplazamiento son magnitudes a controlar.

Automatización industrial

Robots, líneas de fabricación, trenes, procesos de envasado y control de temperatura.

Arquitectura de un equipo de control

Elementos

  • Computador: ejecuta el programa y procesa datos.
  • Sensores: convierten magnitudes físicas en señales eléctricas.
  • Accionadores: cambian el sistema físico a partir de órdenes.
  • Interfaz operador: permite supervisión y mando manual.
  • Comunicaciones: enlazan con otros equipos o redes.

Bloque 02

Señales, muestreo y lógica temporal

Señales continuas y discretas

En el mundo físico, las magnitudes cambian de forma continua: temperatura, velocidad, presión, posición.

En el computador, los valores son discretos porque solo se pueden almacenar y procesar en instantes determinados.

x(t)   →   {x(k)}

Cada muestra se obtiene cada periodo Tm (tiempo de muestreo), y el programa trabaja con la secuencia actual y previa.

Periodo de muestreo

El tiempo de muestreo define la frecuencia con la que el computador observa el sistema.

t = k · Tm
  • Si Tm es muy grande: el sistema se responde demasiado tarde.
  • Si Tm es muy pequeño: se obtiene más detalle, pero se aumenta la carga computacional.

Programa básico de control

while (1) {
    ref_k = LeerReferencia();
    y_k = LeerSalida();
    u_k = CalculoAccionDeControl(y_k, ref_k);
    AplicarAccionDeControl(u_k);
    Sleep(Tm);
}

Este patrón se mantiene vigente: medir, decidir y actuar de forma repetitiva; la diferencia hoy es la integración con sensores, redes, protocolos y mayor robustez.

Valores actuales y anteriores

Muchas decisiones no dependen solo de la lectura actual, sino de la evolución reciente.

  • Velocidad basada en la diferencia entre muestras.
  • Filtro temporal para suavizar ruido.
  • Control proporcional o derivativo con memoria histórica.

Ejemplo

u(k) = f(y(k), y(k-1), r(k))

La historia de la señal se almacena en memoria para realizar cálculos más fiables.

Ejemplo cotidiano: regar una planta

  • Periodo de muestreo: 1 día.
  • Historia: lluvia de los últimos siete días.
  • Decisión: regar hoy si el balance y la humedad lo requieren.

Este tipo de esquema temporal es exactamente el mismo que usa un controlador automatizado: acumular información, evaluar el estado y actuar según un criterio.

Adquisición analógica

El sensor genera una tensión o corriente proporcional a la magnitud física. El ADC convierte esa señal analógica en un valor digital que el programa puede entender.

u_in → ADC(n bits) → valor entero

Características clave

  • Rango de entrada: umin a umax
  • Resolución: 8, 10, 12, 16, 24 bits
  • Se requiere adaptación si la tensión del sensor no coincide con el rango del ADC

Ejemplo: temperatura con termopar

int adk;
float vad_k, vhc_k, th_k;
float s = 43e-6f; // V/°C

adk = LeerAD();
vad_k = adk * 5.0f / 1023.0f;
vhc_k = vad_k / 500.0f;
th_k = vhc_k / s;

El principio sigue siendo válido: la señal del sensor se adapta, se digitaliza y luego se transforma al valor físico que interesa medir.

Bloque 04

Control secuencial y lazo de control

Control secuencial

El control secuencial define una secuencia de estados y transiciones: “si ocurre esto, pasa a aquello” o “si el tiempo supera X, realiza una acción”.

  • Secuencia de etapas
  • Transiciones por tiempo, entradas u otros eventos
  • Especialmente útil en automatización y procesos por etapas

Ejemplo de control secuencial

Una carretilla debe:

  1. moverse a carga
  2. esperar 5 s
  3. moverse a descarga
  4. esperar 2 s
  5. repetir o detenerse

Si aparece una alarma o un fin de carrera, el sistema debe pasar a un estado seguro y detener la secuencia.

Lazo de control

El lazo de control se centra en mantener una variable de salida cerca de una referencia.

error = referencia - salida

El controlador calcula la acción adecuada para reducir ese error a cero, con la velocidad y precisión requeridas.

  • Medir
  • Comparar
  • Decidir
  • Actuar
  • Repetir

Control secuencial vs. lazo de control

Enfoque Control secuencial Lazo de control
Objetivo Ordenar eventos y tiempos Mantener una variable en un valor
Base Estados y transiciones Error y corrección
Ejemplo Secuencia de una línea de producción Temperatura de un horno o velocidad de motor

Bloque 05

Matemática y algoritmos del control

Matemáticas del control

Conceptos fundamentales

  • Señal de referencia
  • Señal de salida
  • Error
  • Acción de control
  • Periodo de muestreo

Idea clave

El control digital reemplaza el análisis continuo por un modelo discreto que se ejecuta a intervalos regulares, y esto es exactamente lo que hace una aplicación industrial actual.

Tipos de acción de control

Regulación on/off

Enciende o apaga el actuador según el valor de una banda.

Proporcional

La acción es proporcional al error actual.

PID

Combina proporcional, integral y derivativa para responder mejor a la dinámica del proceso.

En la práctica actual, el algoritmo puede estar en un PLC, un microcontrolador, un sistema embebido o en una aplicación de supervisión con control distribuido.

¿Qué hemos aprendido hasta aquí?

  • El control no es solo “programar”: es modelar el proceso, medirlo y reaccionar en el momento correcto.
  • La digitalización del mundo físico exige considerar tiempos, resolución y robustez.
  • La automatización moderna conserva estas bases aunque utilice PLCs, microcontroladores o computación en la nube.

Programación en C para control

Lenguaje C en control

Por qué C

  • Es cercano al hardware.
  • Permite gestionar operaciones binarias y temporales.
  • Es preciso, eficiente y compatible con sectores industriales.

Conceptos básicos

  • Variables y tipos
  • Condicionales
  • Bucles
  • Funciones
  • Operaciones bit a bit

Ejemplo de bucle de control

float ref_k, y_k, u_k;

while (1) {
    ref_k = LeerReferencia();
    y_k = LeerSalida();
    u_k = CalculoAccionDeControl(y_k, ref_k);
    EscribirSalida(u_k);
    delay_ms(50);
}

Memoria y señales

En ingeniería de control, la memoria no es un detalle: es la forma de guardar los valores previos de una señal y así poder evaluar tendencias, derivadas y estados del sistema.

v[k], v[k-1], v[k-2], ...

Es habitual usar arrays o buffers para desplazar la historia temporal del sistema.

Operaciones binarias

En control industrial, se trabaja con bits, máscaras y banderas. Esto es esencial para:

  • interpretar entradas digitales
  • leer alarmas
  • manejar relés y salidas
  • comunicar con PLCs y buses industriales
estado = entrada & MASK;

Actualización del contexto

Los conceptos del PDF siguen vigentes, pero la implementación actual incluye nuevas herramientas y paradigmas:

  • Comunicación industrial: Ethernet/IP, Modbus TCP, OPC UA, CAN, MQTT.
  • Supervisión: HMI, dashboards web, SCADA moderno.
  • Edge computing: procesamiento local antes de enviar datos a la nube.
  • Seguridad: mecanismos de robustez, diagnóstico y recuperación ante fallos.

Resumen y cierre

Resumen final

Qué debemos recordar

  • Un sistema físico necesita sensores, control y actuadores.
  • El error y la referencia son la base del control.
  • El muestreo transforma el mundo continuo en datos digitales.

Qué debe hacerse bien

  • Diseñar la interfaz entre realidad y software.
  • Elegir el periodo de muestreo adecuado.
  • Programar con lógica segura, legible y robusta.

Preguntas para reflexionar

  • ¿Qué magnitud física queremos controlar en un proceso real?
  • ¿Cómo afecta el periodo de muestreo a la estabilidad del sistema?
  • ¿Qué criterio define si un actuador debe encenderse o apagarse?
  • ¿Qué papel tiene la seguridad y la diagnóstica en un sistema industrial?

Conclusión

El control por computador combina electrónica, matemáticas, programación y automatización. Aunque la tecnología ha evolucionado, los principios fundamentales siguen siendo los mismos: observar, decidir y actuar con precisión, rapidez y fiabilidad.

Hoy se sigue enseñando lo mismo que hace décadas, pero con sistemas, protocolos y herramientas más modernos, más conectados y más integrados en la industria digital.
