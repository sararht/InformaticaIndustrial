Comunicación

Intercambio de información entre dos o más dispositivos mediante un medio físico y una interfaz bajo reglas comunes:

Medio e Interfaz Medio: Elemento físico por el que circula la información, y características de dicho medio.
Interfaz: Adaptación eléctrica y lógica entre el dispositivo y el medio físico.
Trama y Protocolo Trama: Unidad de información a transmitir (secuencia ordenada de bytes).
Protocolo: Conjunto de reglas que definen cómo intercambiar tramas de forma fiable y ordenada entre dispositivos (interfaz, formato de trama, errores...).
Emisor / Receptor Dispositivo/programa que genera y envía la trama frente a quien la recibe.
Cliente / Servidor Dispositivo/programa que inicia la petición frente a quien espera conexiones.

Topologías de Comunicación

Cómo se conectan físicamente los dispositivos entre sí

1. Punto a punto: Un único emisor y un receptor.
  • Serie: RS-232, USB
  • Paralelo (en desuso)
  • Inalámbrica: Bluetooth
2. En bus: varios emisores y receptores, todos conectados al mismo medio físico.
  • Serie: RS-485, I2C, SPI, CAN
3. En red: varios emisores y receptores, no todos conectados al mismo medio físico.
  • Cableada: Ethernet
  • Inalámbrica: WiFi

Capa de Aplicación

La programación de comunicaciones a nivel de capa de aplicación implica:
  • Codificar en tramas los contenidos a transmitir.
  • Definir la secuencia de comunicación: conexión, envío/recepción, fin de conexión.
  • Identificar al receptor en comunicaciones multi-punto.
  • Protocolo de acceso al medio si no existe en capas inferiores.
  • Detección/corrección de errores si no existe en capas inferiores.
Equipos “pequeños” (sin S.O.) Interfaz a nivel de puertos e interrupciones (o librerías).
Equipos “grandes” (con S.O.) Programación a nivel de dispositivos de E/S (S.O. / drivers).

Comunicaciones en C: Flujo General y Codificación

Esquema general al programar un enlace (Programa A ↔ Programa B)
  • 1. Abrir dispositivo: puerto serie, red o bus → identificador/manejador (device).
  • 2. Seguir el protocolo del Programa B: secuencia de mensajes, direcciones/IDs y reglas acordadas.
  • 3. Elegir codificación de trama según el protocolo: texto legible (ASCII) o bytes (Binario).
1. Protocolo Tipo Texto (ASCII) Legible por humanos; cadenas delimitadas (ej. \n) con sprintf/sscanf. 

                  char snd[TAM_MAX_SEND], rcv[TAM_MAX_RECV];
                  // Componer en send con sprintf(), strcpy(), strcat()
                  sprintf(snd, "POS=%d\n", 90);

                  Funcion_Write(device, snd, strlen(snd));
                  Funcion_Recv(device, rcv, TAM_MAX_RECV);

                  // Extraer desde recv con strcmp(), strchr(), strstr(), sscanf(), atoi(), atof()
                  sscanf(rcv, "TEMP=%f", &temp);
Ej: Tramas NMEA de GPS ($GNGGA,...).
2. Protocolo Binario (Bytes) Más compacto y rápido; estructura fija y atención a Big / Little Endian. 

              uint8_t snd[TAM_MAX_SEND], rcv[TAM_MAX_RECV];

              // Componer en send según contenido de la trama. Ojo little/big endian
              Funcion_Write(device, snd, len_trama_snd);
              Funcion_Recv(device, rcv, len_trama_recv);
              
              // Obtener desde recv según contenido de la trama. Ojo little/big endian
Ej: Modbus RTU, TMCL, paquetes NTP.

Transmisión de Datos: Serie vs. Paralelo

1. Comunicación en Paralelo

Envía varios bits simultáneamente (ej. 1 byte completo = 8 bits a la vez) utilizando un hilo dedicado para cada bit.

  • Ventaja: Alto caudal a baja frecuencia (envía toda la palabra en un solo pulso).
  • Inconvenientes: Mucho cableado/pines, mayor coste, desfase temporal a largas distancias e interferencias entre cables vecinos.
2. Comunicación en Serie (Secuencial)

Envía los datos bit a bit de forma secuencial (en fila india) a través de una única línea de datos.

  • Ventajas: Mínimo cableado y pines, menor coste, mayor inmunidad a interferencias y mayores distancias.
  • Compromiso: Requiere frecuencias de reloj mucho más altas para igualar el caudal y registros de conversión Paralelo ↔ Serie.

Comunicación en Serie

Estándares de comunicación serie
  • UART (RS-232, RS-485): distancias medias/largas (metros a cientos de metros), baja velocidad.
  • I2C, SPI: distancias muy cortas (cm), alta velocidad.
  • USB: conexión estándar de periféricos al PC (alta velocidad, punto a punto).
  • Buses industriales (CAN, Profibus, Modbus...): entornos con ruido eléctrico y tiempo real.

Comunicaciones Serie UART (Universal Asynchronous Receiver-Transmitter)

  • Transmisión serie: todos los bits se transmiten por un mismo hilo, uno después de otro
  • Comunicación asíncrona: no hay línea de reloj compartida; emisor y receptor acuerdan previamente la velocidad (baudrate) y el formato de trama.
  • Sin pila de red intermedia: el programador define el formato de mensajes, turnos, direcciones y control de errores en aplicación/protocolo.
  • Estándares físicos habituales sobre UART:
    • RS-232: enlace punto a punto
    • RS-485: bus multipunto.

Comunicación Serie Asíncrona (UART) y Enlace RS-232

1. Trama Asíncrona en Línea TD (Sin hilo de reloj)

Cada equipo usa su reloj interno. La línea reposa a 1 , baja a 0 (Start) un periodo, envía los datos y cierra con un bit de paridad (opcional) y uno o varios de Stop (1)

2. Parámetros de Configuración (Iguales en ambos extremos)
  • Baudrate: velocidad en bps (ej. 9600, 115200).
  • Bits de datos: 5 a 8 bits (habitual: 8).
  • Paridad (detección básica de errores): None, Even (n.º par de unos) o Odd (n.º impar de unos).
  • Bits de Stop: 1, 1.5 ó 2 bits.
3. RS-232: Enlace Punto a Punto
4. Programación del Puerto Serie en C
  • C estándar (FILE*, fopen, fclose): no permite configurar baudrate, formato ni líneas de control.
  • API del Sistema Operativo:
    • Windows: HANDLE, CreateFile(), ReadFile(), WriteFile().
    • Linux (POSIX): open(), read(), write() + tcgetattr(), tcsetattr(), ioctl().

Capa Física en Bus: RS-485 (sobre UART)

Protocolo en Bus: Maestro / Esclavos
  • El maestro siempre inicia la secuencia.
  • Cada esclavo tiene un ID único (habitualmente 1 a 255).
  • El 1er byte de la trama indica el ID del esclavo destinatario.
  • Tras recibir respuesta (o timeout), el maestro lanza la siguiente petición.
Half dúplex (2 líneas: par trenzado + GND)
Full dúplex (4 líneas: dos pares trenzados cruzados TD↔RD + GND)

Comunicaciones Serie Síncronas: I2C y SPI

Características generales: Cortas distancias (cm), alta velocidad (decenas de Mbps) y reloj compartido (síncronos). Maestro: genera el reloj. Esclavo: usa el reloj del maestro.
I2C (2 hilos: SCL y SDA + Pull-Up) Maestro / Esclavo
  • SCL (reloj en serie del maestro) y SDA (datos en serie); habitual con sensores y módulos.
  • El maestro envía dirección del esclavo + bit R/W, el esclavo responde con ACK si coincide, se intercambian datos (con ACK) y el maestro cierra con STOP.
SPI (Full-duplex: MOSI, MISO, SCLK/SCK, SS) Full-duplex
  • MOSI (salida maestro → entrada esclavo) y MISO (entrada maestro ← salida esclavo) transmiten a la vez con reloj SCLK/SCK.
  • SS (selección de esclavo, activo en bajo) habilita el esclavo; sin dirección en trama, más rápido y simple que I2C.

Comunicaciones en Red: TCP/IP y UDP

Dirección IP Identifica el equipo o interfaz en la red (ej. 192.168.1.50).
Puerto Identifica el proceso o servicio dentro del equipo (0–65535).
El par IP + puerto define el destino concreto de la comunicación.
Cliente / Servidor El servidor espera peticiones; el cliente inicia la comunicación.
Protocolos de transporte

Conjunto de protocolos para comunicar equipos a través de redes (LAN, Internet) mediante routers y switches.

TCP — Transporte con conexión
  • Conexión punto a punto (IP + puerto): conexión → envío/recepción → cierre.
  • Fiable y ordenado: flujo de bytes con troceado, reconstrucción, control de orden y reintentos ante pérdidas.
  • Uso típico: HTTP, transferencia de ficheros o comandos críticos.
UDP — Transporte sin conexión
  • Envío y recepción de datos a cualquier destino (IP + puerto).
  • Rápido y ligero, pero no seguro: sin retardo de confirmación ni garantía de entrega u orden.
  • Uso típico: telemetría periódica en tiempo real, vídeo o NTP.
En C se programan ambos mediante sockets.

Comunicaciones en Red: Arquitectura TCP/IP

Dirección IP (32 bits: x.x.x.x) Identifica al equipo en la red. Puede ser estática (fija) o dinámica (asignada por servidor DHCP). El DNS traduce nombres (isa.uniovi.es) a IP.
Puerto IP (0 a 65535) Identifica al programa concreto dentro del equipo.
• 0–1023: Estándar (HTTP: 80, SSH: 22, NTP: 123).
• > 49151: Aplicaciones de usuario.
[Cliente: 192.168.1.38] ──▶ [Router: LAN 192.168.1.1 | NAT | WAN Pública] ═══ (Internet) ═══ [Servidor: 156.35.152.5:80]
El Router (Gateway) enlaza la red local (LAN) con el exterior (WAN) traduciendo direcciones mediante NAT.

Programación de Sockets en C: Inicialización

Un socket es el extremo de comunicación (IP + Puerto). Cabeceras: <sys/socket.h> (Linux) o <winsock2.h> (Windows).

int sock; // En Windows: SOCKET sock;

// 1. Crear socket (SOCK_STREAM para TCP, SOCK_DGRAM para UDP)
sock = socket(AF_INET, SOCK_STREAM, 0);

// 2. Asociar dirección IP y puerto local (obligatorio en servidores)
struct sockaddr_in addr_local;
addr_local.sin_family = AF_INET;
addr_local.sin_addr.s_addr = INADDR_ANY; // Cualquier interfaz local
addr_local.sin_port = htons(5000);       // Puerto en formato de red (Big Endian)

int err = bind(sock, (struct sockaddr*)&addr_local, sizeof(addr_local));

Programación de Sockets UDP en C

Tras crear el socket (SOCK_DGRAM) y hacer bind(), se envían y reciben datagramas indicando la estructura de dirección del interlocutor:

struct sockaddr_in addr_destino; // Rellenar IP (inet_addr) y puerto (htons)
socklen_t len = sizeof(addr_destino);

// Enviar datagrama:
sendto(sock, buffer_snd, tam_snd, 0, (struct sockaddr*)&addr_destino, len);

// Recibir datagrama (bloqueante hasta que llegue un paquete):
int n = recvfrom(sock, buffer_rcv, TAM_MAX, 0, (struct sockaddr*)&addr_origen, &len);

close(sock); // Cerrar socket al finalizar
Un mismo socket UDP puede comunicarse con múltiples destinos distintos cambiando addr_destino.

Programación de Sockets TCP en C

LADO CLIENTE 
// 1. Conectar con el servidor
connect(sock, (struct sockaddr*)&addr_srv,
        sizeof(addr_srv));

// 2. Intercambiar datos
send(sock, msg, strlen(msg), 0);
int n = recv(sock, buf, TAM_MAX, 0);

// 3. Cerrar conexión
close(sock);
LADO SERVIDOR 
// 1. Poner socket en escucha (tras bind)
listen(sock, 5);

// 2. Aceptar cliente (crea nuevo socket)
int conn = accept(sock, (struct sockaddr*)
                  &addr_cli, &len);

// 3. Intercambiar datos usando 'conn'
int n = recv(conn, buf, TAM_MAX, 0);
send(conn, resp, strlen(resp), 0);
close(conn);
