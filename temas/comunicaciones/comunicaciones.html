Comunicaciones

Mecanismo(s) de intercambio de información entre 2 ó más computadores conectados entre sí o a través de otros.

Terminología:
  • Trama: unidad de información a transmitir (secuencia de bytes).
  • Medio: elemento físico por el que circula la información, y características de dicho medio.
  • Interfaz: conexión del computador al medio físico.
  • Emisor: dispositivo/programa que genera y envía una trama.
  • Receptor: dispositivo/programa que debe recibir y procesar una trama.
  • Cliente: dispositivo/programa que inicia una secuencia de comunicación.
  • Servidor: dispositivo/programa que espera una comunicación.
  • Protocolo: conjunto de todas las características de la comunicación para que sea viable (interfaz, codificación de tramas, control de errores, secuenciación de tramas, ...).

Comunicaciones

Punto a punto: sólo hay un emisor y un receptor
  • Serie (RS-232, USB) | Paralelo | Inalámbrica (Bluetooth)
En bus: varios emisores y receptores, todos conectados al mismo medio físico
  • Serie (RS-485, I2C, SPI, CAN, ...)
En red: varios emisores y receptores, no todos conectados al mismo medio físico
  • Red cableada (Ethernet) | Red inalámbrica (Wifi)

Comunicaciones

La programación de comunicaciones a nivel de capa de aplicación:

  • Codificar en tramas los contenidos a transmitir.
  • Definir la secuencia de comunicación: establecimiento de conexión, envío/recepción, fin de conexión.
  • Identificar al receptor en comunicaciones multi-punto.
  • Establecer protocolo de acceso al medio si no existe en las capas inferiores.
  • Establecer método de detección/corrección de errores si no existe en las capas inferiores.
Equipos "pequeños" (sin S.O.) Programación del interfaz a nivel de puertos e interrupciones (o librerías disponibles).
Equipos "grandes" (con S.O.) Programación a nivel de dispositivos de E/S.

Comunicaciones serie y en bus

Protocolos estándar de comunicación serie:

  • UART (RS-232, RS-485): largas distancias (metros o cientos de metros), baja velocidad (menor que 1 Mbps).
  • I2C, SPI: pequeñas distancias (cm), alta velocidad (decenas de Mbps).
  • USB
  • Otros (industriales): CAN, ProfiBus, ...
Características principales:
  • Síncrono / asíncrono (con / sin señal de reloj).
  • Velocidad (bits por segundo).
  • Selección de esclavo (sólo en caso de bus).

Comunicaciones serie tipo UART

  • Todos los bits se transmiten por un mismo hilo, uno después de otro.
  • Sin niveles intermedios entre la capa de aplicación y el medio físico: todo es responsabilidad del programador.
  • Estándares más usados:
    • RS-232: punto a punto
    • RS-485: multi-punto
Las señales RS-232 son single-ended (referidas a masa común).
RS-232: Configuración mínima (DB9)
[Equipo A]             [Equipo B]
TD (Pin 3) ───────────▶ RD (Pin 2)
RD (Pin 2) ◀─────────── TD (Pin 3)
GND (Pin 5) ─────────── GND (Pin 5)
Otros pines DB9: Pin 1 DCD, Pin 4 DTR, Pin 6 DSR, Pin 7 RTS, Pin 8 CTS, Pin 9 RI.

Comunicaciones serie RS-232

  • La línea de transmisión TD se mantiene a 1 (Mark) si no hay datos que enviar.
  • Cada equipo usa su propio reloj.
  • Antes del comienzo de datos, se baja la línea TD a 0 (Space) durante un periodo (start bit).
  • Se envían los bits de un dato a impulsos del reloj (LSB primero: bit 0 a bit 7).
  • Al finalizar un dato, se envía un bit de paridad (opcional) y uno o varios de stop (línea a 1).
Mark (1) ───┐         ┌───┬───┬───┬───┬───┬───┬───┬───┬───────┐
            │  Start  │ 0 │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │ 7 │ Stop  │ Start
Space (0)   └─────────┴───┴───┴───┴───┴───┴───┴───┴───┘       └────

Comunicaciones serie RS-232

Los programas de los dos equipos conectados tienen que utilizar los mismos parámetros de comunicación:

  • Baudrate: velocidad de reloj (bits/segundo).
    Valores normalizados: 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200, 230400, 460800, 921600.
  • Número de bits de datos: 5 a 8.
  • Uso de paridad: par (even), impar (odd), ninguna (none).
  • Número de bits de stop: 1, 1.5 ó 2.
  • Sincronización hardware: líneas auxiliares RTS/CTS (Request To Send / Clear To Send).
  • Sincronización software: bytes especiales XON/XOFF.

Comunicaciones en bus RS-485

  • Estrategia maestro/esclavos | Niveles de tensión diferencial (no single-ended).
  • Necesarias resistencias de terminación (120 Ω) en los extremos del bus.
Half dúplex (2 líneas + GND)
[Master] ═══ (DATA B+ / DATA A-) ═══ [Slave 1] ══ [Slave 2] ══ [Slave 3]
Un par trenzado y masa
Full dúplex (4 líneas + GND)
[Master TD±] ══▶ [Slaves RD±]
[Master RD±] ◀══ [Slaves TD±]
Dos pares trenzados y masa

Comunicaciones en bus RS-485

  • El maestro siempre inicia la comunicación.
  • Los esclavos deben tener un identificador único (número del 1 al 255).
  • El 1er byte transmitido por el maestro indica el ID del esclavo que debe responder.
  • Una vez recibida la respuesta del esclavo, el maestro puede comenzar una nueva secuencia de comunicación.

Comunicaciones serie I2C y SPI

Para pequeñas distancias (cm) y alta velocidad (decenas de Mbps). Habituales con sensores y accionadores integrados.

Bus I2C (2 hilos + Pull-Up)
  • SDA: Datos | SCL: Reloj (Maestro → Esclavos).
  • Trama: START → Dir. Esclavo (7 bits) + bit R/W → ACK → Datos (8 bits) + ACK → STOP.
Bus SPI (4 hilos, Full-Duplex)
  • SCLK: Reloj | MOSI: Master Out Slave In | MISO: Master In Slave Out.
  • SS (Slave Select): Se pone en bajo (0) todo el tiempo que dure la comunicación con el esclavo elegido.

Funciones del sistema de comunicación:

  • Establecimiento de conexiones y multiplexación

Comunicaciones en red TCP/IP

Protocolo de red IP (Internet Protocol): Identificación de nodo: dirección IP (4 bytes) | Identificación de programa usuario: nº de puerto.
Protocolo de transporte con conexión: TCP
  • Conexión punto a punto (dirección IP + nº puerto): Conexión → envío de datos → cierre conexión.
  • Conexión segura: asegura que no hay pérdida de mensajes, el troceado, la reconstrucción y el orden.
Protocolo de transporte sin conexión: UDP
  • No hay conexión. Envío y recepción de datos a cualquier punto (dirección IP + nº puerto).
  • Envío y recepción no seguros.

Comunicaciones en red TCP/IP

Protocolo de encaminamiento IP: hace llegar paquetes a destino mediante routers. Valor de 32 bits (x.x.x.x).

  • Estática: fija, para equipos siempre en el mismo lugar | Dinámica (DHCP): variable, asignada por servidor DHCP.
  • Global: única y accesible desde cualquier equipo (servidores) | Local: puede repetirse en subredes (clientes).
  • DNS: servidor de nombres como "agenda" para direcciones IP.

El papel del router

El router (o gateway) conecta físicamente los equipos. Dispone de 2 tipos de conexiones, cada una con su IP:

  • LAN: con los equipos cercanos (cableadas Ethernet e inalámbricas WiFi).
  • WAN: con el resto de la red (típicamente cableada).
[Equipos LAN: 192.168.1.XXX, Mask: 255.255.255.0, GW: 192.168.1.1]
▲ (Eth / WiFi A.P.)
[ROUTER: LAN IP 192.168.1.1 (DHCP) | NAT | WAN IP 156.35.152.KKK] ──▶ Siguiente Router (156.35.152.1)

El papel del router

Conexiones LAN en el router:

  • Todas:
    • Las direcciones IP de todos los clientes deben estar en la misma subred y ser diferentes.
    • Requieren configuración de IP, Subnet y Gateway en el cliente (Estática o Dinámica vía DHCP).
    • Gateway: dirección a la que se envían paquetes con destino a otras redes.
    • Subnet: bits que indican qué parte de la dirección IP se considera en la misma subred.
  • Cableadas (Ethernet): negocian con el router parámetros de conexión (velocidad, etc.).
  • Inalámbricas (WiFi): negocian canal/velocidad y requieren nombre de A.P. y contraseña.

El papel del router

El protocolo NAT (Network Address Translation) en el router:

  • Equipos conectados a routers diferentes pueden tener la misma dirección IP local (subredes distintas).
  • Al enviar hacia fuera, el router modifica la IP/puerto origen mediante NAT antes de reenviar; a la recepción hace el trabajo inverso.
Paquete LAN: Desde 192.168.1.XXX:pppp → Para 156.35.152.5:qqqq [MSG]
⬇ Traducción NAT en Router ⬇
Paquete WAN: Desde 156.35.152.KKK:rrrr → Para 156.35.152.5:qqqq [MSG]

Comunicaciones en red

Una secuencia típica: conexión a red de cliente y servidor

1. Cliente y servidor: conexión a red
  • Conexión física/enlace con el router (velocidad + canal/contraseña en WiFi).
  • Configuración IP fija o mediante protocolo DHCP (IP local, gateway, subred y DNS).
2. Para cada envío:
  • Se envía cada paquete al router más cercano (gateway).
  • El router aplica NAT y reenvía al siguiente router.
  • El router con conexión directa al receptor entrega el paquete con la ruta de respuesta.

Comunicaciones en red UDP/IP

Secuencia típica: cliente/servidor de tiempos (NTP)

Cliente (desea obtener hora actual)
  1. Solicitud a DNS de la IP del servidor.
  2. Envío de paquete UDP de solicitud (formato NTP).
  3. Espera respuesta del servidor.
  4. Procesamiento de respuesta para obtener fecha/hora.
Servidor (espera solicitudes)
  1. Recibe y comprueba solicitud UDP.
  2. Compone y envía respuesta según especificación NTP.

Comunicaciones en red TCP/IP

Secuencia típica: cliente/servidor de páginas web (HTTP/HTTPS)

Cliente
  1. Solicitud DNS → IP del servidor.
  2. Conexión mediante protocolo TCP.
  3. Negociación TLS (si es HTTPS).
  4. Envío solicitud HTML (GET + servidor + página) encriptada si procede.
  5. Espera respuesta, desencripta y presenta página web.
Servidor
  1. Acepta conexión TCP.
  2. Inicia negociación TLS (si HTTPS).
  3. Espera solicitud GET y desencripta.
  4. Compone, encripta (si procede) y envía respuesta con contenido HTML.

Programación sockets TCP / UDP

Librería básica Windows/Linux (socket): identificación de conexión punto a punto (IP + puerto). Incluir <socket.h> (en Windows "winsock2.h", tipo SOCKET).

int sock; // Declaración de identificador

// 1er paso: crear id. válido de socket (SOCK_STREAM para TCP, SOCK_DGRAM para UDP)
sock = socket(AF_INET, SOCK_STREAM, 0);

// 2º paso: asignar puerto local al socket
struct sockaddr_in add_local;
// Rellenar campos de add_local: dirección IP, puerto (network order), protocolo
err = bind(sock, (struct sockaddr*) &add_local, sizeof(struct sockaddr_in));

Comunicaciones en red UDP/IP

Programación de sockets sin conexión (UDP):

// Enviar datos:
ssize_t sendto(int sockfd, const void *buf, size_t len, int flags,
               const struct sockaddr *dest_add, socklen_t add_len);

// Recibir datos:
ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags,
                 struct sockaddr *src_addr, socklen_t *addrlen);

// Cerrar el socket:
close(sock);
  • Con el mismo socket se puede enviar a diferentes destinatarios (incluso broadcast).
  • No hay seguridad de llegada ni de orden aunque err == 0; el usuario debe trocear/recomponer mensajes grandes.

Programación sockets TCP/IP

Establecimiento de conexión modelo cliente/servidor. Asegura llegada, orden y troceado automático.

LADO CLIENTE 
struct sockaddr_in addr_servidor;
// Rellenar campos de addr_servidor
err = connect(sock, (struct sockaddr*)
      &addr_servidor, sizeof(addr_servidor));

// Enviar y recibir:
send(sock, ...);
recv(sock, ...);
close(sock);
LADO SERVIDOR 
err = listen(sock, n_conex_max);

struct sockaddr_in addr_cliente;
int len = sizeof(addr_cliente);
conn = accept(sock, (struct sockaddr*)
       &addr_cliente, &len);

// Enviar y recibir con socket conn:
send(conn, ...);
recv(conn, ...);
close(conn);
