Comunicación

Intercambio de información entre dos o más dispositivos mediante un medio físico y una interfaz bajo reglas comunes:

Medio e Interfaz Medio: Elemento físico por el que circula la información, y características de dicho medio.
Interfaz: Adaptación eléctrica y lógica entre el dispositivo y el medio físico.
Trama y Protocolo Trama: Unidad de información a transmitir (secuencia ordenada de bytes).
Protocolo: Conjunto de reglas que definen cómo intercambiar tramas de forma fiable y ordenada entre dispositivos (interfaz, formato de trama, errores...).
Emisor / Receptor Dispositivo/programa que genera y envía la trama frente a quien la recibe.
Cliente / Servidor Dispositivo/programa que inicia la petición frente a quien espera conexiones.

Topologías de Comunicación

Cómo se conectan físicamente los dispositivos entre sí

1. Punto a punto: Un único emisor y un receptor.
  • Serie: RS-232, USB
  • Paralelo (en desuso)
  • Inalámbrica: Bluetooth
2. En bus: varios emisores y receptores, todos conectados al mismo medio físico.
RS-485, I2C, SPI, CAN...
3. En red: varios emisores y receptores, no todos conectados al mismo medio físico.
Ethernet cableada, WiFi.

Topologías de Comunicación

Cómo se conectan físicamente los dispositivos entre sí

1. Punto a punto

Enlace exclusivo y dedicado entre dos únicos equipos.

  • Serie: RS-232, USB
  • Paralelo (en desuso)
  • Inalámbrica: Bluetooth
2. Multipunto: En Bus

Varios nodos comparten el mismo cable físico (requiere turnos o ID).

  • Industrial: RS-485, CAN
  • En placa PCB: I²C, SPI
3. Multipunto: En Red

Nodos interconectados mediante equipos de encaminamiento.

  • Cableada: Ethernet
  • Inalámbrica: WiFi
  • Arquitectura TCP/IP

Clasificación General de las Comunicaciones

Cuatro criterios independientes para caracterizar cualquier enlace

1. Topología (¿Quién habla con quién?)
  • Punto a punto: 2 equipos directos (RS-232, USB).
  • En bus: Varios en el mismo cable (RS-485, I²C, SPI, CAN).
  • En red: Varios vía switches/routers (Ethernet, WiFi).
2. Nivel Físico (¿Cómo viajan los bits?)
  • Serie Asíncrono: Sin hilo de reloj; sincroniza por Baudrate (RS-232, RS-485).
  • Serie Síncrono: Con línea dedicada de reloj en placa PCB (I²C, SPI).
  • Paralelo: Varios bits a la vez por varios hilos (en desuso).
3. Transporte en Red (Si usamos TCP/IP)
  • TCP (Con conexión): Canal fiable y ordenado (HTTP, control crítico).
  • UDP (Sin conexión): Envío rápido de datagramas sin confirmación (NTP, telemetría).
4. Formato de Trama (Tu código en C)
  • Texto (ASCII): Cadenas legibles (sprintf / sscanf, GPS NMEA).
  • Binario: Bytes crudos (uint8_t[]; vigilar Endianness, Modbus).
Regla práctica: Toda comunicación se define eligiendo una opción de cada bloque (ej. Punto a punto + RS-232 + ASCII, o En red + TCP + Binario).

Capa de Aplicación

La programación de comunicaciones a nivel de capa de aplicación implica:
  • Codificar en tramas los contenidos a transmitir.
  • Definir la secuencia de comunicación: conexión, envío/recepción, fin de conexión.
  • Identificar al receptor en comunicaciones multi-punto.
  • Protocolo de acceso al medio si no existe en capas inferiores.
  • Detección/corrección de errores si no existe en capas inferiores.
Equipos “pequeños” (sin S.O.) Interfaz a nivel de puertos e interrupciones (o librerías).
Equipos “grandes” (con S.O.) Programación a nivel de dispositivos de E/S (S.O. / drivers).

Comunicaciones en C: Flujo General y Codificación

Esquema general al programar un enlace (Programa A ↔ Programa B)
  • 1. Abrir dispositivo: puerto serie, red o bus → identificador/manejador (device).
  • 2. Seguir el protocolo del Programa B: secuencia de mensajes, direcciones/IDs y reglas acordadas.
  • 3. Elegir codificación de trama según el protocolo: texto legible (ASCII) o bytes (Binario).
1. Protocolo Tipo Texto (ASCII) Legible por humanos; cadenas delimitadas (ej. \n) con sprintf/sscanf[cite: 7, 8]. 

            char snd[TAM_MAX_SEND], rcv[TAM_MAX_RECV];
            // Componer en send con sprintf(), strcpy(), strcat()
            sprintf(snd, "POS=%d\n", 90);

            Funcion_Write(device, snd, strlen(snd));
            Funcion_Recv(device, rcv, TAM_MAX_RECV);

            // Extraer desde recv con strcmp(), strchr(), strstr(), sscanf(), atoi(), atof()
            sscanf(rcv, "TEMP=%f", &temp);
Ej: Tramas NMEA de GPS ($GNGGA,...)[cite: 7, 8].
2. Protocolo Binario (Bytes) Más compacto y rápido; estructura fija y atención a Big / Little Endian[cite: 7, 8]. 

        uint8_t snd[TAM_MAX_SEND], rcv[TAM_MAX_RECV];

        // Componer en send según contenido de la trama. Ojo little/big endian
        Funcion_Write(device, snd, len_trama_snd);
        Funcion_Recv(device, rcv, len_trama_recv);
        
        // Obtener desde recv según contenido de la trama. Ojo little/big endian
Ej: Modbus RTU, TMCL, paquetes NTP[cite: 7, 8].

Transmisión bit a bit por un mismo canal. Se diferencian por sincronismo (con/sin reloj), distancia y número de nodos:

Ambos equipos deben configurar exactamente los mismos parámetros:

  • Baudrate: Velocidad en bits/segundo (ej. 9600, 19200, 38400, 115200 bps).
  • Formato de palabra: Bits de datos (5 a 8), Paridad (None, Even, Odd) y Bits de Stop (1, 1.5 ó 2).
  • Control de flujo (opcional): Hardware (RTS/CTS) o Software (XON/XOFF).
Programación en C: En Windows (CreateFile, ReadFile, WriteFile); en Linux (open, read, write, tcsetattr).

Buses Industriales y de Placa: RS-485, I²C y SPI

Bus Industrial RS-485
  • Tensión diferencial (DATA+ / DATA-): alta inmunidad al ruido eléctrico y largas distancias.
  • Maestro / Esclavos: El maestro inicia siempre; el 1er byte indica el ID del esclavo (1..255).
  • Requiere resistencias de terminación (120 Ω) en los extremos.
Buses en Placa (Sensores / Actuadores)
  • I²C (2 hilos + Pull-Up): SDA (datos) y SCL (reloj). Direccionamiento por software (7 bits + bit R/W + ACK).
  • SPI (4 hilos, Full-Duplex): SCLK, MOSI, MISO y selección por hardware mediante pin SS (activo a nivel bajo).

Comunicaciones en Red: Arquitectura TCP/IP

Dirección IP (32 bits: x.x.x.x) Identifica al equipo en la red. Puede ser estática (fija) o dinámica (asignada por servidor DHCP). El DNS traduce nombres (isa.uniovi.es) a IP.
Puerto IP (0 a 65535) Identifica al programa concreto dentro del equipo.
• 0–1023: Estándar (HTTP: 80, SSH: 22, NTP: 123).
• > 49151: Aplicaciones de usuario.
[Cliente: 192.168.1.38] ──▶ [Router: LAN 192.168.1.1 | NAT | WAN Pública] ═══ (Internet) ═══ [Servidor: 156.35.152.5:80]
El Router (Gateway) enlaza la red local (LAN) con el exterior (WAN) traduciendo direcciones mediante NAT.

Protocolos de Transporte: TCP vs. UDP

TCP (Orientado a Conexión)
  • Establece canal punto a punto antes de transmitir (connect → datos → close).
  • Fiable: Garantiza llegada sin pérdidas, en orden y trocea/recompone mensajes grandes.
  • Uso: Web (HTTP), ficheros (FTP), comandos críticos.
UDP (Sin Conexión)
  • Envía datagramas directamente a una IP + Puerto sin handshake previo.
  • No fiable pero muy rápido: Sin retardo de confirmación; soporta envío broadcast.
  • Uso: Telemetría en tiempo real, vídeo, sincronización NTP.

Programación de Sockets en C: Inicialización

Un socket es el extremo de comunicación (IP + Puerto). Cabeceras: <sys/socket.h> (Linux) o <winsock2.h> (Windows).

int sock; // En Windows: SOCKET sock;

// 1. Crear socket (SOCK_STREAM para TCP, SOCK_DGRAM para UDP)
sock = socket(AF_INET, SOCK_STREAM, 0);

// 2. Asociar dirección IP y puerto local (obligatorio en servidores)
struct sockaddr_in addr_local;
addr_local.sin_family = AF_INET;
addr_local.sin_addr.s_addr = INADDR_ANY; // Cualquier interfaz local
addr_local.sin_port = htons(5000);       // Puerto en formato de red (Big Endian)

int err = bind(sock, (struct sockaddr*)&addr_local, sizeof(addr_local));

Programación de Sockets UDP en C

Tras crear el socket (SOCK_DGRAM) y hacer bind(), se envían y reciben datagramas indicando la estructura de dirección del interlocutor:

struct sockaddr_in addr_destino; // Rellenar IP (inet_addr) y puerto (htons)
socklen_t len = sizeof(addr_destino);

// Enviar datagrama:
sendto(sock, buffer_snd, tam_snd, 0, (struct sockaddr*)&addr_destino, len);

// Recibir datagrama (bloqueante hasta que llegue un paquete):
int n = recvfrom(sock, buffer_rcv, TAM_MAX, 0, (struct sockaddr*)&addr_origen, &len);

close(sock); // Cerrar socket al finalizar
Un mismo socket UDP puede comunicarse con múltiples destinos distintos cambiando addr_destino.

Programación de Sockets TCP en C

LADO CLIENTE 
// 1. Conectar con el servidor
connect(sock, (struct sockaddr*)&addr_srv,
        sizeof(addr_srv));

// 2. Intercambiar datos
send(sock, msg, strlen(msg), 0);
int n = recv(sock, buf, TAM_MAX, 0);

// 3. Cerrar conexión
close(sock);
LADO SERVIDOR 
// 1. Poner socket en escucha (tras bind)
listen(sock, 5);

// 2. Aceptar cliente (crea nuevo socket)
int conn = accept(sock, (struct sockaddr*)
                  &addr_cli, &len);

// 3. Intercambiar datos usando 'conn'
int n = recv(conn, buf, TAM_MAX, 0);
send(conn, resp, strlen(resp), 0);
close(conn);

Clasificación General de las Comunicaciones

Cuatro criterios independientes para caracterizar cualquier enlace de datos

1. Según Topología (Conexión entre nodos)
  • Punto a punto: Solo 2 equipos unidos directamente (RS-232, USB, Bluetooth).
  • Bus: Varios nodos comparten el mismo cable físico con turnos (RS-485, I2C, SPI, CAN).
  • Red: Interconexión mediante switches y routers (Ethernet, WiFi).
2. Según Nivel Físico (Transmisión de bits)
  • Serie Asíncrono (UART): Sin hilo de reloj; sincroniza por Baudrate y bits Start/Stop (RS-232, RS-485).
  • Serie Síncrono: Con línea dedicada de reloj para alta velocidad en placa PCB (I2C, SPI).
  • Paralelo: Múltiples bits simultáneos por varios hilos (en desuso frente a serie).
3. Según Transporte en Red (Sockets TCP/IP)
  • TCP (Con conexión): Establece canal previo; garantiza entrega sin pérdidas y en orden (HTTP, control crítico).
  • UDP (Sin conexión): Envío directo de datagramas; máxima velocidad sin confirmación (telemetría, NTP).
4. Según Formato de Trama (Capa Aplicación en C)
  • Texto (ASCII): Cadenas legibles delimitadas por \n; se tratan con sprintf() y sscanf() (ej. GPS NMEA).
  • Binario: Secuencias de bytes crudos (uint8_t[]); compactas y rápidas, requieren vigilar el Endianness (ej. Modbus, NTP).
Regla práctica: Toda comunicación se define eligiendo una opción de cada bloque (ej. Punto a punto + RS-232 + Trama ASCII, o bien En red + TCP + Trama Binaria).
